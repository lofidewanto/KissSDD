Step 4 of 7 · first quality gate

Review and Approve

A bug found in the plan costs one line of text to fix. The same bug found in the code costs a code change, a test change and another review. So the plan gets reviewed by more than one LLM, and a human approves it.

Human + AIReviewers: Opus 5.5 (fresh session) + GPT Sol 6.1Output: plan v2, approved

4a · The review prompt

Anna uses the same prompt for both reviewers. The Opus reviewer runs in a new session, so it doesn't defend its own plan.

Terminal · new session
> You are a strict reviewer. Compare docs/user-story-plan/001-manage-prompts.md
  with GitHub issue #1 and TECH-SPEC.md.
  Find: missing ACs/BRs, wrong logic, unhandled errors, violations of
  TECH-SPEC.md, and over-engineering. Give each finding an ID (R-x),
  a severity (high/medium/low) and a concrete fix. Do not change any file.

4b · Findings and human decisions

The reviewers make suggestions. Anna makes the decisions, and she rejects a finding when it goes against KISS.

IDFindingFound bySeverityAnna's decision
R-1validatePrompt checks title uniqueness against all prompts. On edit, the prompt clashes with itself, so you can't save an edit that keeps the title. Fix: add an ignoreId parameter.BothhighAccept
R-2BR-3 says tags are stored in lowercase without duplicates. The plan doesn't say where that happens. Fix: normalizeTags() (trim, lowercase, dedupe) plus parseTagInput() for the comma field, both with tests.GPT Sol 6.1mediumAccept
R-3localStorage.setItem throws when storage is full. AC-8 asks for a clear message. Fix: savePrompts returns an error message instead of throwing.Opus 5.5mediumAccept
R-4Corrupt JSON in storage makes loadPrompts throw, and the app stays blank. Fix: return an empty list plus a warning.Opus 5.5mediumAccept
R-5Debounce the search input for performance.GPT Sol 6.1lowReject: a few hundred prompts filter in under 1 ms. KISS.
R-6Add JSON export as a backup against data loss.Opus 5.5lowLater: out of scope in issue #1, so it goes in the next story.

Two reviewers, different findings. Both found R-1. Each found something the other missed. That's why KissSDD says “one or more LLMs”.
