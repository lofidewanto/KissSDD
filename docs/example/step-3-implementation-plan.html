# Plan 001 – Manage prompts (Issue #1)

## Goal
Single-page app to create, list, search, edit, delete and copy prompts,
stored in localStorage. Follows TECH-SPEC.md (no framework, no build).

## Files
| File                     | Purpose                              |
|--------------------------|--------------------------------------|
| app/index.html           | Form, search field, list container   |
| app/prompt-store.js      | Domain logic (no DOM)                |
| app/app.js               | Rendering and event handling         |
| app/prompt-store.test.js | Unit tests (node --test)             |
| app/package.json         | "type": "module", script "test"      |

## prompt-store.js – API
- validatePrompt(draft, prompts) -> string[]         BR-1, BR-2, BR-3
- createPrompt(prompts, draft, now) -> {prompts, errors}       AC-1
- updatePrompt(prompts, id, draft, now) -> {prompts, errors}   AC-4
- deletePrompt(prompts, id) -> prompts                         AC-5
- sortByUpdated(prompts) -> prompts (newest first)            AC-2
- searchPrompts(prompts, query) -> prompts                    AC-3
- loadPrompts(storage) -> prompts                             AC-7
- savePrompts(storage, prompts)                               AC-7
- `now` is a parameter so tests control time.

## app.js – UI
- Form: title, text, tags (comma-separated). One form for create and
  edit; "Cancel" leaves edit mode.
- List item: title, updated date, text (pre), tag chips,
  buttons Copy / Edit / Delete.
- Delete asks with confirm()                                  AC-5
- Copy uses navigator.clipboard.writeText + status message   AC-6
- Validation errors shown in a list under the form           AC-8
- All user data rendered with textContent                     BR-4
- Empty state text when there are no prompts                  AC-2

## Tasks
1. package.json + test skeleton
2. prompt-store.js: validation (BR-1..3) with tests
3. prompt-store.js: create / update / delete / sort / search with tests
4. prompt-store.js: load / save with fake storage, tests
5. index.html + app.js
6. Run all tests, fix failures
7. Manual check of AC-1..AC-8 in the browser

## Tests (unit)
AC-1 create · AC-2 sort · AC-3 search title/text/tag, case-insensitive
AC-4 edit keeps createdAt · AC-5 delete only one · AC-7 save+load
BR-1 required / max 100 / unique · BR-2 required / max 10,000
BR-3 max 5 tags / allowed characters / max 20
Manual only: AC-5 confirm dialog, AC-6 clipboard, BR-4 rendering

## Risks / open questions
- Clipboard API needs HTTPS or localhost (OK for GitHub Pages).

Spot the gaps? Before you go on, read the plan once more. What happens when a user edits a prompt and keeps its title? Or when localStorage is full? Step 4 answers this.
