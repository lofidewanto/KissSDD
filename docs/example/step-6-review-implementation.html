Step 6 of 7 · second quality gate

Review and Approve Again

Green tests only show that the code does what the tests check. A top-tier model reviews the code against the specs, and Anna tries every acceptance criterion in the browser. Only then does she approve.

Human + AIReviewer: Opus 5.5Output: fixes + approval

6a · The review prompt

Terminal · claude --model opus · new session
> Review the uncommitted changes (git diff) against GitHub issue #1,
  TECH-SPEC.md and docs/user-story-plan/001-manage-prompts.md.
  Look for: bugs, security problems, violations of TECH-SPEC.md,
  ACs that are not met, and tests that were weakened.
  Give each finding an ID (F-x), a severity and a fix. Change nothing.

6b · Findings and decisions

IDFindingSeverityDecision
F-1XSS. app.js builds the list item header with innerHTML and puts in the title. A prompt titled <img src=x onerror=alert(1)> runs script. Breaks BR-4 and TECH-SPEC §3. Fix: build elements with createElement + textContent.highFix
F-2Copy: when navigator.clipboard.writeText fails (no permission, insecure context), the promise is rejected silently and the user sees nothing. Breaks AC-8. Fix: try/catch with a message.mediumFix
F-3Delete the prompt that is open in the edit form, then click “Save changes”: you get “Prompt not found.” Fix: leave edit mode when that prompt is deleted.mediumFix
F-4Replace confirm() with a custom modal dialog for a nicer look.lowReject: AC-5 is met. KISS.
F-5Checked the test change from step 5 ("writ" → "writing"). The test still checks tag search and is not weaker.infoOK
F-6Found by Anna in the manual check (6d), not by the reviewer. Opened from disk (file://), the page stays empty: no list and no “No prompts yet” hint, so AC-2 fails. Browsers block <script type="module"> on file://. Fix: load prompt-store.js and app.js as classic scripts; the store publishes one global, PromptStore.highFix
F-7Found by the AI while it wrote a regression test for AC-2. Two prompts saved in the same millisecond have the same updatedAt, and the sort keeps them oldest first. Fix: an edited prompt moves to the end of the list, and the sort uses the list position when timestamps are equal. Two new tests.mediumFix

Why the tests didn't catch F-1. The unit tests cover prompt-store.js, and the bug was in the UI code. Step 1 wrote BR-4 down, step 2 made it a coding standard, and so the reviewer had a clear rule to check against. Only what the spec names gets hardened.

Sonnet 5.5 applies F-1 to F-3, then F-6 and F-7 after the manual check. It runs the tests again (16/16 green, two of them new for F-7).

Der Mensch fand, was beide LLMs übersehen hatten. Alle Unit-Tests waren grün und das Code-Review war erledigt – trotzdem startete die App nicht so, wie Anna sie öffnete. Deshalb endet Schritt 6 mit einem Menschen, der jedes Akzeptanzkriterium ausprobiert, und nicht mit einem grünen Testlauf.
