An excerpt: the business rules in code

Note the ignoreId parameter. It's there because of review finding R-1 in step 4.

app/prompt-store.js
export function validatePrompt(draft, prompts, ignoreId = null) {
  const errors = [];
  const title = String(draft.title ?? '').trim();
  const text = String(draft.text ?? '');
  const tags = normalizeTags(draft.tags);

  if (!title) errors.push('Title is required.');
  else if (title.length > LIMITS.titleMax) errors.push(`Title must be at most ${LIMITS.titleMax} characters.`);
  else {
    const taken = prompts.some(
      (p) => p.id !== ignoreId && p.title.toLowerCase() === title.toLowerCase(),
    );
    if (taken) errors.push('A prompt with this title already exists.');
  }
  // ... BR-2 text, BR-3 tags
  return errors;
}

AI analysis
AI

The test searches for "writ" and expects only the prompt tagged writing. But the other prompt's text is "Write JUnit tests", which also contains “writ”. AC-3 says search covers the text too, so the code is right and the test data is wrong.

Fix: search for "writing", which only matches the tag. This test was written in this story and hasn't been approved yet, so changing it is allowed (TECH-SPEC §5).

Watch this decision. “Make the test green” can also mean “make the test useless”. That's why the prompt asks the AI to say why it changes a test, and why step 6 checks it again. Tests from earlier stories are off-limits.
