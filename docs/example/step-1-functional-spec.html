Manage prompts in a simple web app #1 user-story Open

User Story

As a developer who works with AI assistants, I want to save, find, edit and copy my prompts in one place, so that I can reuse good prompts instead of rewriting them.

Business process

  1. The user opens the app and sees all saved prompts.
  2. The user creates a prompt, or finds an existing one with the search.
  3. The user copies the prompt text and pastes it into the AI tool.
  4. The user edits a prompt to improve it, or deletes it when it's no longer needed.

Acceptance criteria

  • AC-1 Create: Given the form is filled with a valid title, text and optional tags, when I click “Save prompt”, then the prompt appears in the list and the form is empty again.
  • AC-2 List: Given saved prompts, when I open the app, then I see all prompts, sorted by last change, newest first. With no prompts, I see a hint to create the first one.
  • AC-3 Search: When I type into the search field, then the list shows only prompts whose title, text or a tag contains the search text, ignoring case.
  • AC-4 Edit: When I click “Edit”, change fields and save, then the prompt is updated and moves to the top of the list.
  • AC-5 Delete: When I click “Delete”, then I'm asked to confirm. Only after I confirm is the prompt removed.
  • AC-6 Copy: When I click “Copy”, then the prompt text is in my clipboard and I see a short confirmation.
  • AC-7 Persist: Given saved prompts, when I reload the page or reopen the browser, then the prompts are still there.
  • AC-8 Errors: Invalid input shows a clear message next to the form and nothing is saved. If prompts can't be saved or read, I see a clear message.

Business rules

  • BR-1 Title is required, 1–100 characters after trimming, and unique, ignoring case.
  • BR-2 Text is required, at most 10,000 characters.
  • BR-3 At most 5 tags. Each tag has 1–20 characters, only a–z, 0–9 and -. Tags are stored in lowercase, without duplicates.
  • BR-4 Prompt title, text and tags are always shown as plain text. HTML in a prompt is never interpreted (security).

Domain model

Prompt
  id         unique, generated
  title      text   (BR-1)
  text       text   (BR-2)
  tags       list of text (BR-3)
  createdAt  date-time, set once
  updatedAt  date-time, changes on every edit

Data model

One JSON array of prompts in the browser's localStorage under the key kisssdd.prompts.v1. The v1 suffix allows a later migration.

Out of scope

  • Export / import as JSON (→ next story)
  • User accounts, sharing, sync between devices

Done when …

  • The story has the form “As a … I want … so that …”.
  • Every acceptance criterion can be tested with a clear yes or no.
  • Limits are written down as numbers (100, 10,000, 5, 20). Only what the spec names gets hardened.
  • What is not part of the story is written down too.

Prompts in einer einfachen Web-App verwalten #1 user-story Offen

User Story

Als Entwickler, der mit KI-Assistenten arbeitet, möchte ich meine Prompts an einem Ort speichern, finden, bearbeiten und kopieren, um gute Prompts wiederzuverwenden, statt sie neu zu schreiben.

Geschäftsprozess

  1. Der Nutzer öffnet die App und sieht alle gespeicherten Prompts.
  2. Der Nutzer legt einen Prompt an oder findet einen vorhandenen über die Suche.
  3. Der Nutzer kopiert den Prompt-Text und fügt ihn im KI-Tool ein.
  4. Der Nutzer bearbeitet einen Prompt, um ihn zu verbessern, oder löscht ihn, wenn er ihn nicht mehr braucht.

Akzeptanzkriterien

  • AC-1 Anlegen: Angenommen, das Formular enthält einen gültigen Titel, Text und optionale Tags, wenn ich auf „Save prompt“ klicke, dann erscheint der Prompt in der Liste und das Formular ist wieder leer.
  • AC-2 Liste: Angenommen, es gibt gespeicherte Prompts, wenn ich die App öffne, dann sehe ich alle Prompts, sortiert nach letzter Änderung, neueste zuerst. Ohne Prompts sehe ich einen Hinweis, den ersten anzulegen.
  • AC-3 Suche: Wenn ich in das Suchfeld tippe, dann zeigt die Liste nur Prompts, deren Titel, Text oder ein Tag den Suchtext enthält – ohne Beachtung der Groß-/Kleinschreibung.
  • AC-4 Bearbeiten: Wenn ich auf „Edit“ klicke, Felder ändere und speichere, dann wird der Prompt aktualisiert und rückt an den Anfang der Liste.
  • AC-5 Löschen: Wenn ich auf „Delete“ klicke, dann werde ich um Bestätigung gebeten. Erst nach der Bestätigung wird der Prompt entfernt.
  • AC-6 Kopieren: Wenn ich auf „Copy“ klicke, dann ist der Prompt-Text in meiner Zwischenablage und ich sehe eine kurze Bestätigung.
  • AC-7 Speichern: Angenommen, es gibt gespeicherte Prompts, wenn ich die Seite neu lade oder den Browser neu öffne, dann sind die Prompts noch da.
  • AC-8 Fehler: Ungültige Eingaben zeigen eine klare Meldung am Formular, und nichts wird gespeichert. Wenn Prompts nicht gespeichert oder gelesen werden können, sehe ich eine klare Meldung.

Geschäftsregeln

  • BR-1 Der Titel ist Pflicht, 1–100 Zeichen nach dem Trimmen, und eindeutig ohne Beachtung der Groß-/Kleinschreibung.
  • BR-2 Der Text ist Pflicht, höchstens 10.000 Zeichen.
  • BR-3 Höchstens 5 Tags. Jeder Tag hat 1–20 Zeichen, nur a–z, 0–9 und -. Tags werden kleingeschrieben und ohne Duplikate gespeichert.
  • BR-4 Titel, Text und Tags werden immer als reiner Text angezeigt. HTML in einem Prompt wird nie interpretiert (Sicherheit).

Entitätsmodell

Prompt
  id         eindeutig, generiert
  title      Text   (BR-1)
  text       Text   (BR-2)
  tags       Liste von Texten (BR-3)
  createdAt  Datum/Uhrzeit, einmal gesetzt
  updatedAt  Datum/Uhrzeit, ändert sich bei jeder Bearbeitung

Datenmodell

Ein JSON-Array mit allen Prompts im localStorage des Browsers unter dem Schlüssel kisssdd.prompts.v1. Das Suffix v1 erlaubt später eine Migration.

Nicht im Umfang

  • Export / Import als JSON (→ nächste Story)
  • Benutzerkonten, Teilen, Synchronisierung zwischen Geräten

Fertig, wenn …

  • die Story die Form „Als … möchte ich …, um …“ hat.
  • jedes Akzeptanzkriterium mit einem klaren Ja oder Nein testbar ist.
  • Grenzen als Zahlen festgehalten sind (100, 10.000, 5, 20). Nur was in der Spezifikation steht, wird abgesichert.
  • auch festgehalten ist, was nicht zur Story gehört.
